# Verification record — 2026-10-01

The tested deliverable is an original C11 creative voxel client/server targeting the Java Edition 1.8.9 wire protocol (47), extended with NBT-backed inventory state and native inventory controls. This record does not assert complete Minecraft feature parity.

## Verified

- Windows UCRT64 GCC 15.2.0 Release build through CMake/Ninja, with `-std=c11 -Wall -Wextra -Wpedantic -Werror`: passed.
- Windows CTest: all eleven groups passed: protocol, world, item, NBT, inventory, multiplayer, inventory-network, public-audit, client-self-test, client-network and client-inventory.
- Network codec/transport: 495 checks, including fragmented/coalesced frames, signed VarInt, packed positions, UTF-8, offline UUID, zlib, malformed input, bounded queues, partial writes and read-half-close backlog draining.
- World: negative coordinates, deterministic original terrain, block edits, transactional save/reload, corrupt-load rollback and save failure.
- Item registry: 336 legacy item IDs, stack limits, resource-name lookup, metadata variants, block-state mapping and simple collision boundaries.
- NBT: exact unknown-data preservation, all target tags, malformed/deep/oversized input, Java modified UTF-8, transactional getters/read/copy, semantic compound and floating-point equality, gzip CRC/truncation/size validation and atomic persistence.
- Inventory: 188 checks covering counts, NBT, normal/right/Shift/number/clone/drop/drag/collect operations, rollback, existing overstacks, armor restrictions, saturated capacities and interleaved creative updates. Crafting-output and item-entity integration remain unsupported.
- Inventory network: eight independent Python tests cover full NBT and equipment, metadata placement, click confirmations and mismatch locks, reconnect persistence, cursor/unknown-field/root-name preservation, resource-name and legacy numeric item IDs, aggregate metadata rejection and pre-login rejection of an external near-limit player file.
- Native client inventory: seven independent compressed-peer tests cover unknown NBT/cursor/overstack retention, direct player-slot index mapping, no automatic hotbar overwrite, negative-confirmation acknowledgement, delayed slot/cursor resync in both orders, invalid automation input, malformed inventory rollback and server game-mode changes revoking creative operations.
- Independent Python TCP peers: eight server tests, covering status/login, two players, movement/chat/edit visibility, restart persistence, Japanese chat, malformed input, failed-save rollback, half-close response and a height-255 tower at the original spawn.
- Actual C client: six independent network tests, covering the real C server, external compressed framing, keepalive and position acknowledgement, explicit online-mode rejection, malformed chunk rejection, unloaded spawn protection and descent from above build height.
- Public file audit: six real Git fixture tests, including staged forbidden/binary contents even when the working tree has been changed back to clean text.
- WSL Ubuntu: strict GCC builds and complete `scripts/test-linux.sh` passed, including the Linux CLI client, codec/world/item/NBT/inventory checks, eight multiplayer tests, eight inventory tests, six audit fixtures and both client network suites.
- WSL AddressSanitizer/UndefinedBehaviorSanitizer: all 495 protocol/transport checks passed without diagnostics.
- WSL AddressSanitizer/UndefinedBehaviorSanitizer with leak detection: NBT and all 188 inventory checks passed without diagnostics. The headless client self-test and independent inventory peer tests also passed under these sanitizers.
- Independent [PrismarineJS implementation](https://github.com/PrismarineJS/node-minecraft-protocol), `minecraft-protocol` 1.68.0: two version-1.8.9 clients received 25 chunks each and synchronized full NBT creative slots/equipment, right-click splitting, Japanese chat, movement and digging. The library was used only under ignored `.local/interop/`.
- Actual local original 1.8.9 game JAR: read a C-created gzip player inventory, resolved string item IDs, retained Japanese names/enchantments/damage and accepted Java→C→Java Slot bytes. Isolated game-container probes established legacy overstack Shift-transfer and creative-drag semantics, plus NBT floating/collection equality. This exercised the named game code, not a complete vanilla GUI multiplayer session. Private JARs, dependencies, mappings and reflection harnesses remain ignored and undistributed.
- Native rendering: a hidden Win32 window rendered the actual received world through OpenGL on an AMD Radeon RX 6700 XT. The 1280×800 framebuffer was inspected for terrain, trees, HUD, crosshair, hotbar and connection information. Generated screenshots are ignored build outputs.
- Inventory layout: own hidden Win32/OpenGL fixtures rendered the inventory at 1280×800 and inventory/creative screens at 560×620. The framebuffers were inspected for keyboard focus, long Japanese item names, count 127, carried NBT and pending/rejected transactions without overlapping captions/status. These fixtures establish layout behaviour; network behaviour is established by the independent peer tests above.
- Independent code review: material findings fixed and re-reviewed for EOF draining, position arithmetic, spawn selection, staged-blob auditing, Unicode message limits, unloaded terrain physics, inventory resync ordering, signed-window slot mapping, legacy overstack transfers, tall collision shapes and inactive-window inventory input.

## Unverified or unsupported

Vanilla Minecraft GUI gameplay and live keyboard/mouse/IME input were not manually exercised. The native framebuffer and protocol paths were exercised; GUI input wiring was inspected and targeted helpers were tested. An online-mode server requires authentication/encryption that this initial version explicitly does not implement.

The renderer uses independently generated cube materials and symbolic item icons. It does not reproduce all block models, transparency, textures or lighting. Simple collision shapes cover tested slabs/stairs/carpet/snow and local shapes; neighbour-dependent connections and full physics remain incomplete. Chat text and `extra` fields are supported; translation, rich styles and localization are simplified. The dedicated server has a bounded 7×7-chunk creative world. Crafting output, dropped item entities, complete container screens, vanilla close-return/drop semantics, Survival, mobs, redstone, Anvil world saves and Java mods are not implemented. Registry inclusion does not imply every item's gameplay behaviour or complete creative variant coverage.

GitHub-hosted CI is configured separately. Its status must be checked from the actual pushed commit; local results alone do not establish remote CI success.
