# Verification record — 2026-10-01

The tested deliverable is an original C11 creative voxel client/server targeting the Java Edition 1.8.9 wire protocol (47), extended with NBT-backed inventories, native controls, player 2×2 crafting and durable world-item transfers. This record does not assert complete Minecraft feature parity.

## Verified

- Windows UCRT64 GCC 15.2.0 Release build through CMake/Ninja, with `-std=c11 -Wall -Wextra -Wpedantic -Werror`: passed.
- Windows CTest: all sixteen groups passed: protocol, world, item, NBT, inventory, crafting, item-entity, transfer, multiplayer, inventory-network, drops-crafting-network, public-audit, client-self-test, client-network, client-inventory and client-entities. The later forced-close and signed-ID changes were also exercised through the affected item/client suites.
- Network codec/transport: 495 checks, including fragmented/coalesced frames, signed VarInt, packed positions, UTF-8, offline UUID, zlib, malformed input, bounded queues, partial writes and read-half-close backlog draining.
- World: negative coordinates, deterministic original terrain, block edits, transactional save/reload, corrupt-load rollback and save failure.
- Item registry: 336 legacy item IDs, stack limits, resource-name lookup, metadata variants, block-state mapping and simple collision boundaries.
- NBT: exact unknown-data preservation, all target tags, malformed/deep/oversized input, Java modified UTF-8, transactional getters/read/copy, semantic compound and floating-point equality, gzip CRC/truncation/size validation and atomic persistence.
- Inventory: 196 checks covering counts, NBT, normal/right/Shift/number/clone/drop/drag/collect operations, rollback, existing overstacks, armor restrictions, saturated capacities and interleaved creative updates. Shift-transfer subtype rules are checked separately from ordinary click/drag equality.
- Crafting: 542 checks for static 2×2 recipes, dynamic repair/dye/firework/book/map/banner NBT, output clicks, number-key/clone/drop, Shift-transfer and remainder/close handling. Independent local original-game differential fixtures matched all 139 registered static 2×2 recipes and established the legacy partially fitting Shift-output rule.
- Item entities: 1691 checks cover complete Slot/NBT packet bytes, bounded and unknown-preserving snapshots, physics/collision/slipperiness, delay/owner/expiry, pickup capacities, Creative remainder discard, damage/subtype-specific merge, damaged/unbreakable tools and the full signed-int32 entity-ID range.
- Transfer recovery: 95 checks cover the manifest commit point, staged checksums and sizes, validation of both files before either replacement, interrupted checkpoint roll-forward, invalid UUID paths, corrupted player/item stages and repeat recovery. These model interrupted commits and I/O failures; actual power-cut testing was not performed.
- Inventory network: eight independent Python tests cover full NBT and equipment, metadata placement, click confirmations and mismatch locks, reconnect persistence, disconnect cursor drops, unknown-field/root-name preservation, resource-name and legacy numeric item IDs, aggregate metadata rejection and pre-login rejection of an external near-limit player file.
- Crafting/drop network: nine independent Python tests exercise output clicks/Shift/number/clone/drop, cursor/input close drops without result duplication, another player's full-NBT pickup after the 40-tick delay, full Creative pickup discard, outside-cursor drops, subtype-specific world merges, corrupt snapshot startup rejection, pre-commit failure preservation and post-commit restart recovery without duplication.
- Native client inventory: seven independent compressed-peer tests cover unknown NBT/cursor/overstack retention, direct player-slot index mapping, no automatic hotbar overwrite, negative-confirmation acknowledgement, delayed slot/cursor resync in both orders, invalid automation input, malformed inventory rollback and server game-mode changes revoking creative operations.
- Native client item/crafting integration: fifteen independent compressed-peer and real-server cases exercise item spawn/metadata/velocity/movement/collection/destruction, full signed-int32 entity and collector IDs, duplicate and nullable metadata ownership, malformed metadata rollback, chunk unload/respawn, Q/Ctrl-Q packets, crafting prediction, normal and server-forced close, queued drag transactions and real C-server drop/pickup synchronization.
- Independent Python TCP peers: eight server tests, covering status/login, two players, movement/chat/edit visibility, restart persistence, Japanese chat, malformed input, failed-save rollback, half-close response and a height-255 tower at the original spawn.
- Actual C client: six independent network tests, covering the real C server, external compressed framing, keepalive and position acknowledgement, explicit online-mode rejection, malformed chunk rejection, unloaded spawn protection and descent from above build height.
- Public file audit: six real Git fixture tests, including staged forbidden/binary contents even when the working tree has been changed back to clean text.
- WSL Ubuntu: strict GCC builds and complete `scripts/test-linux.sh` passed, including all eight C test groups, eight multiplayer tests, eight inventory tests, nine crafting/drop tests, six audit fixtures and all three client network suites. The resulting client included the forced-close change; the later signed-ID change was separately exercised through the affected item/client sanitizer tests.
- WSL AddressSanitizer/UndefinedBehaviorSanitizer: all 495 protocol/transport checks passed without diagnostics.
- WSL AddressSanitizer/UndefinedBehaviorSanitizer with leak detection: NBT, all 196 inventory checks and all 542 crafting checks passed without diagnostics. The earlier headless client self-test and independent inventory peer tests also passed under these sanitizers.
- Final WSL AddressSanitizer/UndefinedBehaviorSanitizer with leak detection: all 1691 item-entity checks, client self-test and all fifteen client item/crafting cases passed without diagnostics, including forced close and the signed-ID regressions.

These fixtures establish layout behaviour; network behaviour is established by the independent peer tests above.
- Crafting/item rendering: updated hidden Win32/OpenGL fixtures rendered the actual 2×2 grid and separate result at 1280×800 and 560×620, pending transactions and long Japanese names/count 127, plus dropped-item geometry with entity ID INT32_MAX. The fixtures also exercised native drag/close helpers. Screenshots remain ignored local outputs.
- Independent code review: material findings fixed and re-reviewed for EOF draining, position arithmetic, spawn selection, staged-blob auditing, Unicode message limits, unloaded terrain physics, inventory resync ordering, signed-window slot mapping, legacy overstack transfers, tall collision shapes, inactive-window input, high-ID rendering overflow and signed entity/collector IDs. Transfer journal recovery and item/crafting ownership were reviewed separately.

## Unverified or unsupported

Vanilla Minecraft GUI gameplay and live keyboard/mouse/IME input were not manually exercised. The native framebuffer and protocol paths were exercised; GUI input wiring was inspected and targeted helpers were tested. An online-mode server requires authentication/encryption that this initial version explicitly does not implement.

The renderer uses independently generated cube materials and symbolic item geometry. It does not reproduce all block models, transparency, textures or lighting. Simple collision shapes cover tested slabs/stairs/carpet/snow and local shapes; neighbour-dependent connections and full physics remain incomplete. Item physics lacks water flow, continuous burning/extinguishing and complete audiovisual effects. Chat text and `extra` fields are supported; translation, rich styles and localization are simplified. The dedicated server has a bounded 7×7-chunk creative world and bounded item snapshots. 3×3 workbench recipes, external container screens, Survival, mobs, redstone, Anvil world saves and Java mods are not implemented. Registry inclusion does not imply every item's gameplay behaviour or complete creative variant coverage.

GitHub-hosted CI is configured separately. Its status must be checked from the actual pushed commit; local results alone do not establish remote CI success.
