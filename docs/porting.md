# Java原本からの移植記録

目標は提供されたJava原本の翻訳です。元のパッケージ・クラス・メソッドに対応するC/C++コードをsrc/minecraft/net/minecraftに置き、状態、参照共有、分岐、通知、呼び出し順を照合します。配置や見た目だけが似ている独自実装を翻訳済みとは数えません。

以下は現在の作業ツリーです。実server/clientの所持品・クラフト・落下アイテム・クリック予測は、原本から翻訳した参照型のクラスを通信・描画・保存へ接続しています。地形・物理・GUI・多くのItem/World/Entity依存先には独自の接続処理が残ります。作業ツリーの結果は、公開コミットやそのCIの結果とは分けて記録します。

native actor/world ownerは元InventoryPlayer/ContainerPlayer、stats、shared stack、owned map snapshotを保持し、クラス試験で接続済みです。必須処理に原本にない空の成功callbackを置きません。原本にある空メソッドはその意味を保ちます。

MCGameplayStorageは正規graphの参照から原版InventoryPlayer/ItemStack/EntityItem NBTメソッドを呼ぶnative保存境界です。未知タグ・UTF-16ルート名、旧保存の作業台入力復旧を保持し、V3 journalの全player/item/mapと送信packet検証へ接続します。失敗したloadは元順の部分変更を含むため、作業graph全体を破棄します。Entityの位置・Motion envelopeはnative依存であり、全Entity.readFromNBT/physicsではありません。統計JSONはStatisticsFile側の未移植依存として残し、player NBTへ独自形式を追加しません。実serverの保存経路はこのencoderを使用します。

util/MCObjectHeapはJavaの参照寿命を接続するC側の環境処理です。同一性・循環・借用中のGC/adopt禁止・全rootを同じmemoで複製するsnapshotを提供します。元copy()は辺ごとの複製、transaction cloneは共有関係の保存です。util/MCGameplayはworld/player/entityの直接参照を保持し、全登録player/items/任意mapsをversion3の単一manifestで保存してから全graphをadoptします。借用中の処理・nested durable transactionを拒否し、確定後のcheckpoint失敗ではadoptした状態で停止・復旧します。MCGameplayPacketsは実S packetを参照のまま保持し、durableSerialで保存未完了のgraphからの送信を止めます。MCGameplayClientPacketsは実C07/C08/C09/C0D/C0E/C0F/C10 packetを保持し、remote worldの全graph検証・client frame採用後にcommitSerialで送信を許可します。共通MCPacketQueueはkindと実class・exact ownerを検証し、Native transportの境界を実装します。client frameはファイル保存もdurableSerial更新も行いません。callback中はparent/working双方を借用し、寿命を保護します。encoder内のpacket preflightを必要とし、成功送信のprefixのみ除去します。再入・送信中のqueue変更も拒否します。実socketはこのqueueを使います。未移植のpacket classはNativePacketの不変encoded messageをtransport境界として使い、別の所持品を所有しません。

実server/clientは正規graphのInventoryPlayer/Container/cursor/EntityItemを直接所有し、独立した確定所持品・pending ACK・rollback backupを保持しません。wireと保存は意図的に独立した参照を復元し、alias IDは保存しません。描画は本体の参照から読みます。毎操作で値型へ戻して本体を再構築し、共有関係を失わせる実装にはしません。

原本との差も残ります。地図同率投票はnative adapterが最初の出現色を選び、元Guava identity-hash列挙順は未移植です。地図96件/viewer64件/装飾256件/entities1024件等のnative上限も元と異なります。新ItemMapData/onCreatedは元short counterのwrapと負damageのconstructor/setter clampを保ち、実runtimeがこのSource経路を使います。未読chunk生成、全次元・World/Entity/GUI、online認証等は未完了です。

公開対象は翻訳したC/C++・native接続・テスト・文書です。Java原本、MCP本体/mapping、JAR、画像/音声/model、private差分harnessと出力はGitへ含めません。公開前はindexの実blobを監査します。[検証記録](verification.md)に実行済みの範囲を記録します。

実runtimeのnative境界はserver/native_gameplay・client/native_runtimeへまとめます。thread identity、Source packetのqueue、inherited actor fields、登録済みrecipe/stat identityとSource drop/pickup効果を接続します。Serverの初期Scoreboardは実際に空のmanaged collectionですが、全Scoreboard class・commands・保存は未移植です。StatisticsFile JSON永続化、achievement chat、TileEntity書込みの未実装依存は成功を偽装しません。Native RNG、EntityItem scalar motion、Spawn/Collect/Destroy/GUI/S34/S37の未移植packet、Win32/OpenGL、チャンク・地形・採掘/設置・移動は元classの翻訳として数えません。Idle tickはworld time/drop throttleだけを正規ownerで進め、所持品/地図/item effectsがあるtickは全graphのdurable commitを行います。

NativeItemMotionの位置範囲は各軸の絶対値67108832以下です。固定小数通信とC側の衝突座標変換を安全に行うためのnative上限であり、Java Entityの制限ではありません。範囲外の保存位置はファイルを保持して拒否し、実行中の範囲外値は作業graphを失敗させます。元EntityのMotion読込時の絶対値10超→0は別途保持します。ClientのInventoryPlayer.decrementAnimations/ItemStack.updateAnimationとGUIのpop効果は未移植です。
