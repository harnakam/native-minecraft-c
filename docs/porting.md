# Java原本からの移植記録

目標は提供されたJava原本の翻訳です。元のパッケージ・クラス・メソッドに対応するC/C++コードをsrc/minecraft/net/minecraftに置き、状態、参照共有、分岐、通知、呼び出し順を照合します。配置や見た目だけが似ている独自実装を翻訳済みとは数えません。

以下は現在の作業ツリーです。実server/clientの所持品・クラフト・落下アイテム・クリック予測は、原本から翻訳した参照型のクラスを通信・描画・保存へ接続しています。地形・物理・GUI・多くのItem/World/Entity依存先には独自の接続処理が残ります。作業ツリーの結果は、公開コミットやそのCIの結果とは分けて記録します。

native actor/world ownerは元InventoryPlayer/ContainerPlayer、stats、shared stack、owned map snapshotを保持し、クラス試験で接続済みです。必須処理に原本にない空の成功callbackを置きません。原本にある空メソッドはその意味を保ちます。

MCGameplayStorageは正規graphの参照から原版InventoryPlayer/ItemStack/EntityItem NBTメソッドを呼ぶnative保存境界です。未知タグ・UTF-16ルート名、旧保存の作業台入力復旧を保持し、V3 journalの全player/item/mapと送信packet検証へ接続します。失敗したloadは元順の部分変更を含むため、作業graph全体を破棄します。Entityの位置・Motion envelopeはnative依存であり、全Entity.readFromNBT/physicsではありません。統計JSONはStatisticsFile側の未移植依存として残し、player NBTへ独自形式を追加しません。実serverの保存経路はこのencoderを使用します。

NativeJavaRandomはJDK 8 scalar APIの独自C依存です。48bit seed、setSeed、next(bits)、nextInt/正のbound、nextLong、boolean/float/double/bytesを実JDKと照合し、nextLongの下位signed int加算とbound棄却時の折返しを保持します。Gaussianのcache・棄却・setSeed時のcache失効をfdlibm log/sqrt依存で接続済みです。stream/serialization/subclassは未実装です。NativeJavaUUIDはimmutableなmost/leastとJava 8のfromString入力契約を接続し、元JDK全classの翻訳とは数えません。nativeエラーはheap失敗として扱うため、Java例外の種類やcatch後の継続全体も未完了です。

World・Player・EntityItemはそれぞれ独立したtraced randを持ちます。native owner factoryはWorldのtemporary Random→updateLCG、World.rand→ambient、Entityのrand→UUID、LivingのMath.random 3回という対象部分を元順で接続します。Entity ctorは全field・provider次元読込・境界箱・watcher・virtual entityInitへ接続済みです。Living/Playerのインスタンスconstructorと属性・health・spawnは同じsource継承ownerへ接続済みです。World/MPの全constructor、potion/combat/Player/SP全tickは未移植です。Itemの基底random部分はwatcherより先に実行し、元3constructor本体は共有Math.randomを使用します。Server dropは渡されたplayer.rand、拾得音はitem.randを読みます。消音判定は元byte4==1です。Client Spawn Objectのnative受信境界はsigned byte角度の元int式を保持し、data>0だけ速度を適用します。data<=0ではposition constructorのmotionを保持します。S0EとhandleSpawnObject全体は未移植です。

PlayerのContainerPlayerには原本どおり!world.isRemoteを渡し、isLocalWorldを保持します。現在の移植済みContainerPlayer本体はこのfieldを分岐に使いませんが、constructorの状態として照合します。

NativeJavaRandomRuntimeはgraph外のプロセス依存です。no-arg seed uniquifier→時計の順とlazy Math.randomを共有し、snapshot/adopt/失敗graph破棄で戻しません。Worldの地形seedとは別です。借用されたruntime/時計contextは全graphより長く生存させます。managed rand/UUIDの参照とscalar状態はmemo cloneで共有関係を保持します。native lockはnextDouble全体を直列化するため、JDKのprimitiveごとのCAS interleavingを完全再現しません。通常のhost logではJDK StrictMathとbit差があるため、許諾されたfdlibm 5.3数値コアを用います。IEEE binary64・nearest-even・gradual underflow・FP contraction無効の環境を確認し、未対応環境のuncached Gaussianはdraw前に失敗します。

util/MCObjectHeapはJavaの参照寿命を接続するC側の環境処理です。同一性・循環・借用中のGC/adopt禁止・全rootを同じmemoで複製するsnapshotを提供します。元copy()は辺ごとの複製、transaction cloneは共有関係の保存です。util/MCGameplayはworld/player/entityの直接参照を保持し、全登録player/items/任意mapsをversion3の単一manifestで保存してから全graphをadoptします。借用中の処理・nested durable transactionを拒否し、確定後のcheckpoint失敗ではadoptした状態で停止・復旧します。MCGameplayPacketsは実S packetを参照のまま保持し、durableSerialで保存未完了のgraphからの送信を止めます。MCGameplayClientPacketsは実C03/C04/C05/C06/C07/C08/C09/C0B/C0D/C0E/C0F/C10/C13 packetを保持し、remote worldの全graph検証・client frame採用後にcommitSerialで送信を許可します。共通MCPacketQueueはkindと実class・exact ownerを検証し、Native transportの境界を実装します。client frameはファイル保存もdurableSerial更新も行いません。callback中はparent/working双方を借用し、寿命を保護します。encoder内のpacket preflightを必要とし、成功送信のprefixのみ除去します。再入・送信中のqueue変更も拒否します。実socketはこのqueueを使います。未移植のpacket classはNativePacketの不変encoded messageをtransport境界として使い、別の所持品を所有しません。

実server/clientは正規graphのInventoryPlayer/Container/cursor/EntityItemを直接所有し、独立した確定所持品・pending ACK・rollback backupを保持しません。wireと保存は意図的に独立した参照を復元し、alias IDは保存しません。描画は本体の参照から読みます。毎操作で値型へ戻して本体を再構築し、共有関係を失わせる実装にはしません。

原本との差も残ります。地図同率投票はnative adapterが最初の出現色を選び、元Guava identity-hash列挙順は未移植です。地図96件/viewer64件/装飾256件/entities1024件等のnative上限も元と異なります。新ItemMapData/onCreatedは元short counterのwrapと負damageのconstructor/setter clampを保ち、実runtimeがこのSource経路を使います。未読chunk生成、全次元・World/Entity/GUI、online認証等は未完了です。

公開対象は翻訳したC/C++・native接続・テスト・文書です。Java原本、MCP本体/mapping、JAR、画像/音声/model、private差分harnessと出力はGitへ含めません。公開前はindexの実blobを監査します。[検証記録](verification.md)に実行済みの範囲を記録します。

実runtimeのnative境界はserver/native_gameplay・client/native_runtimeへまとめます。thread identity、Source packetのqueue、inherited actor fields、登録済みrecipe/stat identityとSource drop/pickup効果を接続します。Serverの初期Scoreboardは実際に空のmanaged collectionですが、全Scoreboard class・commands・保存は未移植です。StatisticsFile JSON永続化、achievement chat、TileEntity書込みの未実装依存は成功を偽装しません。JDK API接続、EntityItem scalar motion、Spawn/Collect/Destroy/S34/S37の未移植packet、Win32/OpenGL、チャンク・地形・採掘/設置・移動は元classの翻訳として数えません。Idle tickも元の所持品更新を呼び、map/entityなしの登録済みbase集合ではanimation/world time/drop throttleだけを正規ownerで進めます。地図/item effectsがあるtickは全graphのdurable commitを行います。

NativeItemMotionの位置範囲は各軸の絶対値67108832以下です。固定小数通信とC側の衝突座標変換を安全に行うためのnative上限であり、Java Entityの制限ではありません。範囲外の保存位置はファイルを保持して拒否し、実行中の範囲外値は作業graphを失敗させます。元EntityのMotion読込時の絶対値10超→0は別途保持します。Clientの元Timerは毎frame一度更新し、signed elapsedTicksが所持品・native item motionの回数を決め、renderPartialTicksがホットバー本体へ渡ります。body geometry/font、プレイヤー全tick・全GUI/RenderItemは未移植です。クリック/Q/chat等とnativeプレイヤー物理は従来どおり毎frame一度の処理であり、全Minecraft.runGameLoop/runTickの翻訳とは数えません。

Item registryは引き続き不変のnative identity adapterです。NULL IDは原本どおり0、未登録identityは-1です。foreign pointerの減算を避け、登録済みobjectとの同一性で照合します。未知のvirtual overrideを原本baseとして成功させません。Source packetが作るNULL Item付きnonnull stackも勝手に消さず、元updateAnimationの正の減算後に失敗します。Java例外class/CrashReport全体は未移植で、native実行環境では失敗を表示して停止します。

EntityItemはfirst memberのEntityを一つだけ持ち、inherited scalar/refを複製しません。実client/serverはSource Entity_construct/setSize/setPositionを呼び、native物理の後も同じ境界箱を更新します。world-only Item constructorの縮小は元boundsのminへ固定され、position constructorはその後setPositionで中心を更新します。全Entity.moveEntityの翻訳ではありません。global signed32 Entity ID serviceはgraph外で進み、失敗graphで戻しません。実join/dropはconstructor IDを保持し、native保存からの再生成は旧C919EntityIdを再利用せずSource constructor IDを保持します。旧保存IDを復元する別のnative load APIは明示的な互換fixture境界です。

Source GameTypeとPlayerCapabilitiesは別の状態です。S39はGameType/allowEditを変えず、能力4booleanと速度2floatを更新します。C13は送られた他のflag/速度から権限を与えず、isFlying && 現在allowFlyingだけをisFlyingへ代入します。原本が許すreserved flag/NaN/負speedはpacket fieldとして保持し、native framingの全payload確認後に処理します。毎frameのnative位置同期は能力をGameTypeで再初期化しません。Native Player factoryはSource Entity/LivingBase/Playerのinstance constructorを一度だけ呼び、能力を保持します。全Player NBTやspeedを用いる全physicsの移植とは数えません。
