# C919 native multiplayer design

Target: Minecraft Java Edition 1.8.9, wire protocol 47, as identified by the local MCP configuration. MCP is a private reference only. No MCP source, binary, mappings, Minecraft assets, or runtime data are distributable inputs.

The objective is complete target-version compatibility as tracked in `docs/compatibility.md`. The initial original C11 creative voxel client and dedicated server are an incomplete starting point. C++ and libraries may be used where necessary. Existing `src/minecraft/net/minecraft` directories are used for readable module boundaries: network framing and codecs, shared world and storage, authoritative server, and native client rendering/input.

The server accepts protocol-47 status/login/play sessions, sends independently generated terrain, maintains players, and synchronizes movement, chat, inventory and validated block edits. Offline identities are explicitly local/LAN identities. The client negotiates framing/compression, receives actual server chunks, entities and inventories, renders procedural original block materials, and sends gameplay actions. World persistence uses a validated C919 format; player inventory persistence uses gzip NBT and target-version resource-name item IDs. Anvil world saves and Java mod execution are not supported.

NBT and Slot ownership is shared by both ends. Inventory operations produce their actual transaction return value and any dropped stack; transport, permissions, world effects and persistence remain caller responsibilities. The server commits durable accepted inventory changes before confirmation. Legitimate return-value mismatches trigger a lock and authoritative resynchronization. The client holds further clicks until a rejection's slots and cursor have both arrived, regardless of fragmentation or order. It does not overwrite an external server's hotbar during login.

Wire parsers bound lengths and reject invalid data. Slow clients have bounded queues. Invalid coordinates, non-finite movement, out-of-range edits, malformed handshakes, and duplicate names are rejected. The server defaults to loopback. Online-mode session authentication and encrypted login are not supported; the client must report this clearly instead of pretending to connect.

Verification: C tests for codecs and world boundaries/persistence; independent Python TCP tests for status/login, fragmented packets, malformed input, multi-client movement/chat/block broadcasts, disconnect cleanup and save/reload; Windows release build; public index audit. Vanilla GUI interoperability is only claimed if actually exercised.
